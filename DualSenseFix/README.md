# DualSense Fix — экспериментальный мост Android 12 без root

**Готовый APK:** [DualSenseFix-debug-arm64.apk](downloads/DualSenseFix-debug-arm64.apk). Откройте файл и нажмите Download raw file. [SHA256](downloads/SHA256SUMS).

Kotlin UI → поддерживаемый Shizuku UserService (UID 2000) → JNI C++17 → evdev/uinput.
Проект независим от Snake-js. Интернет нужен только для сборки; приложение не запрашивает INTERNET.

## Состояние и ограничения

Это прототип для испытаний на телефоне, а не подтверждённое исправление MIUI.
Компиляция и host-тесты не доказывают доступность SELinux/ioctl, доставку событий Android InputReader или работу PPSSPP.
READABLE/WRITABLE не гарантируют успех EVIOCGRAB/UI_DEV_CREATE. Все отказы отображаются в логе.
На реальном Poco X3 Pro здесь испытаний нет: телефон и DualSense к среде не подключены.
Не меняет `/system`, не использует root, Magisk или Accessibility.

## Сборка

Требования: JDK 17 или 21, Android SDK 35, Build Tools 35.0.0, NDK 27.2.12479018, CMake 3.22.1, C++17 host compiler.

```sh
export ANDROID_HOME=/path/to/android-sdk
sdkmanager 'platforms;android-35' 'build-tools;35.0.0' 'ndk;27.2.12479018' 'cmake;3.22.1'
./scripts/test-host.sh
./gradlew --no-daemon assembleDebug lintDebug
```

Подписанный debug APK: `app/build/outputs/apk/debug/app-debug.apk`; только arm64-v8a; minSdk 26, targetSdk 35.
Gradle Wrapper включён; контрольная сумма дистрибутива закреплена.
CI `.github/workflows/android.yml` выполняет тесты/сборку/lint и сохраняет APK. Для использования Actions разместите этот проект в корне отдельного GitHub-репозитория.

## Запуск на Poco

1. Установите APK. Подключите DualSense по Bluetooth. Запустите Shizuku **в ADB-режиме** (wireless debugging или USB ADB), root-режим не поддерживается.
2. Откройте DualSense Fix → «Подключить Shizuku» → разрешите доступ. После подключения в логе/статусе требуется UID **2000**, а не UID приложения.
3. Начните с **Test Inputs**: этот режим не создаёт виртуальный контроллер и не захватывает физический ввод. Подвигайте все элементы по очереди; журнал автоматически показывает тип, код и значение событий, а также диапазоны осей.
4. Для **каждой кнопки** выберите её назначение → Learn → один раз нажмите физическую кнопку. Для каждой оси сначала верните стики в центр/отпустите триггеры, нажмите Learn и перемещайте только выбранную ось. Порог — 20% диапазона, направление сохраняется. Для HAT двигайте D-pad. Если D-pad выдаёт кнопки, обучите четыре D-pad button вместо HAT-осей и удалите строки `a 16 16`/`a 17 17`, если устройство одновременно сообщает оба вида.
5. «Получить выученную карту» → «Сохранить карту». При выходе из диагностики карта **сама не сохраняется**: это исключает непреднамеренную замену профиля. При повторном Learn тот же выход назначается новому физическому коду.
6. Выберите Xbox (по умолчанию) → явно разрешите EVIOCGRAB → Start Bridge → подтвердите захват. Виртуальное устройство создаётся до захвата; при отказе захвата перенаправление отключается и остаётся безопасная диагностика.
7. Откройте Input Report и найдите **DSFIX Virtual Xbox**. Проверьте `KeyLayoutFile`, `Sources` (GAMEPAD/JOYSTICK), `Motion Ranges`: X/Y/Z/RZ около −1…1, LTRIGGER/RTRIGGER около 0…1, HAT_X/HAT_Y −1…1. Экспорт сохранит полный `dumpsys input`, исходные события и карту.
8. Нажмите тест A/Cross: мост пишет press+SYN_REPORT+release+SYN_REPORT в uinput, даже если физический контроллер ещё не подключён. Подтверждение записи в логе **не равно** подтверждению получения Android: проверьте во встроенном **Android Input Tester** (показывает Android KEYCODE/AXIS, имя устройства и Motion Ranges) либо `adb shell getevent -lt /dev/input/eventN` для виртуального устройства. `dumpsys input` подтверждает регистрацию/раскладку, но не получение нажатия игрой.
9. Откройте PPSSPP. Фоновая служба сохраняет heartbeat и уведомление Stop. Разрешите уведомления на Android 13+; на MIUI разрешите фоновую работу приложения. Убийство процесса/службы приводит к освобождению ввода, а не автоматическому перехвату после перезапуска.
10. Stop Bridge в UI или уведомлении останавливает поток, снимает захват и уничтожает uinput. Удаление задачи приложения также останавливает мост. При потере heartbeat нативный watchdog освобождает устройство примерно за 5 секунд. При нормальном Stop ожидание poll до 100 мс; при аварийной смерти shell-процесса Linux закрывает FD и снимает grab.

Проверьте отсутствие двойного ввода: при активном мосте события физического контроллера не должны доходить в игру, одно нажатие даёт ровно одно действие. При Stop исходный DualSense должен снова работать с прежней системной раскладкой. Затем проверьте Bluetooth disconnect/reconnect, остановку Shizuku, закрытие приложения и заблокированный экран.

## Карта и профили

Формат карты — десятичные числа: `k <physical evdev code> <semantic index>`, `a <physical ABS code> <output ABS code>`.
Semantic indexes: A=0, B=1, X=2, Y=3, L1=4, R1=5, L2=6, R2=7, Share=8, Options=9, PS=10, L3=11, R3=12, Up=13, Down=14, Left=15, Right=16.

Из физических кнопок предварительно задан **только Circle: 306 → B**, согласно ТЗ. Все остальные требуется обучить. Непривязанные кнопки только логируются.
Предварительные оси из ТЗ: X→X, Y→Y, Z→RX, RZ→RY, RX→Z, RY→RZ, HAT без перестановки. Это проверяемая гипотеза, не автоматическое определение смысла движения.

Выходные коды проверены по AOSP Android 12:

| Android назначение | Xbox 045e:028e | DualSense 054c:0ce6 |
|---|---|---|
| A/B/X/Y | 304/305/307/308 | 304/305/308/307 |
| L1/R1 | 310/311 | 310/311 |
| Share/Options/PS/L3/R3 | 314/315/316/317/318 | 314/315/316/317/318 |
| Left X/Y | ABS_X/ABS_Y | ABS_X/ABS_Y |
| Right X/Y | ABS_RX/ABS_RY | ABS_RX/ABS_RY |
| L2/R2 analog | ABS_Z/ABS_RZ | ABS_Z/ABS_RZ |

Xbox `.kl` не назначает BUTTON_L2/R2: обученные цифровые L2/R2 синтезируют ABS_Z/ABS_RZ; при наличии аналоговых осей используйте их и не обучайте дублирующие цифровые L2/R2. Sony поддерживает и BUTTON_L2/R2.
Проверка перед созданием читает фактический vendor/product `.kl` на устройстве и отказывается запускаться при несовместимом содержимом. Итоговый выбор Android может зависеть от OEM-файлов, версии устройства и `.idc`: поэтому обязательно проверять **KeyLayoutFile в dumpsys**, а не только VID/PID. При иной OEM-раскладке экспортируйте лог для отдельной адаптации.

Имена виртуальных устройств начинаются с DSFIX и исключаются из discovery. Физический узел выбирается по VID/PID, наличию ABS_X/Y и BTN_GAMEPAD, без фиксированного event9; сенсорные экраны/клавиатуры не захватываются. Для нескольких DualSense выбирается первый подходящий узел.
Стики нормализуются в −32767…32767 с deadzone 4096, триггеры в 0…255 по EVIOCGABS. Направления не инвертируются автоматически. Порядок событий и SYN_REPORT сохраняется; SYN_DROPPED вызывает восстановление текущих ABS/KEY состояний.
При отключении отправляется нейтральное состояние, затем discovery ожидает переподключения. Повторный захват после переподключения действует только в явно запущенной пользователем сессии.

## Диагностика

- `uid != 2000`: перезапустить Shizuku в ADB-режиме; приложение намеренно отказывается работать от root.
- Нет физического узла: убедиться в подключении; экспортировать `dumpsys input`; права shell на evdev зависят от MIUI/SELinux.
- `open /dev/uinput`, UI_DEV_CREATE или EVIOCGRAB denied: это отдельные операции с отдельными проверками. Диагностика не пытается обходить SELinux.
- Ошибка keylayout: выбрать второй профиль, сравнить фактический `.kl`; не выдавать VID/PID за доказательство совместимости.
- Виртуальный геймпад появился, но игра не получает событий: проверить Sources, Motion Ranges, виртуальный getevent и привязки в PPSSPP. Экспортировать лог.
- MIUI убивает приложение: разрешить фоновую работу и уведомления. Watchdog специально прекращает захват при потере связи.

Экспорт создаёт выбранный пользователем текстовый документ через Storage Access Framework, без доступа ко всему хранилищу. `dumpsys input` может включать сведения о других устройствах; просмотрите файл перед публикацией.
